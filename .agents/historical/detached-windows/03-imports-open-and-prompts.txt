ID: GAP-01
Priority: P2
Confidence: High
Trigger: src/js/filepanel/filePanel.js:710 and src/js/filepanel/filePanel.js:2951
Failure: src/js/main/passwordOverlay.js:36 and src/js/main/passwordOverlay.js:103
Minimal user sequence:
1. Run QuiviT with panels detached (main window viewing content, workspace-file-list window showing the file panel).
2. In the detached File List window, navigate to and click (or press Enter on) a password-protected archive.
3. The password modal prompt appears over the viewer in the main window.
4. Immediately type the archive password on the keyboard without manually clicking into the main window.
Expected behavior:
The password prompt in the main window acquires native OS focus so that keyboard input is directed into the password input field. On cancellation via Escape, keyboard focus returns to the initiating File List window.
Actual behavior:
The prompt opens on the viewer in the main window, but the main window never calls window.setFocus(). OS window focus remains with the detached File List window. Keystrokes are received by the detached File List (triggering file search or navigation) rather than the password field. If Escape is pressed while the password prompt is open in non-container mode, _focusFileList() executes on the main window and calls fileListUl.focus() on a hidden element, leaving the interface in a focus vacuum without returning focus to the detached File List window.
Causal chain:
1. User activates an archive row in workspace-file-list, triggering FsUtils.loadFile(path) in filePanel.js:710.
2. In workspace-file-list, FsUtils.configureReplica intercepts the call and sends a workspace request: requestWorkspace('main', 'fs', 'loadFile', [path]).
3. The main window executes FsUtils.loadFile, which invokes list_archive and receives encryption: "password_required".
4. The main window sets Core.setState({ archiveEncryption: 'password_required', ... }) and publishes a snapshot to workspace-file-list.
5. In passwordOverlay.js:108, Core.onStateChange runs on the main window. With state.mode === 'archive', shouldFocus is true, so it executes _show(state.archivePath, enc, shouldFocus).
6. In passwordOverlay.js:36, _show runs requestAnimationFrame(() => _input.focus()).
7. Because the main window does not possess native OS window focus, the DOM focus call cannot steal keyboard focus from the active secondary window without calling window.__TAURI__.window.getCurrentWindow().setFocus().
8. When the prompt is dismissed with Escape in passwordOverlay.js:103, _focusFileList() runs on the main window, calling fileListUl.focus() on #file-panel, which has display: none via main.css:496. No message is sent to focus the detached File List window.
Relocation commit:
Introduced in a628e57 when secondary window hosting was added, and omitted from the focus coordination introduced for cmd-use-url in 35f38e9.

ID: RISK-01
Priority: P2
Confidence: Medium
Trigger: src/js/filepanel/filePanel.js:2115
Failure: src/js/urlLoader.js:2661 and src/js/shared/workspaceSession.js:61
Minimal user sequence:
1. In detached mode, open an active gallery directory with a large list of images.
2. Rapidly scroll the detached File List using a high-resolution mouse wheel or scrollbar drag.
Expected behavior:
Viewport scroll bounds are communicated to the main download queue smoothly without saturating the inter-window request queue.
Actual behavior:
renderVisibleRows runs on every scroll event and synchronously calls setDownloadVisibleRange. In detached mode, urlLoader.js:2661 forwards this call via _workspaceRequest('setVisibleRange', [start, end]). Each call creates an entry in pending with a 30 second timeout and sends an emitTo IPC message. Rapid scrolling generates dozens of requests per second. If pending.size reaches MAX_PENDING_REQUESTS (128), workspaceSession.js:61 rejects the promise with "Too many pending workspace requests", logging errors and dropping range synchronization.
Unresolved assumption / Required runtime check:
Requires runtime observation under fast scrolling to determine whether IPC roundtrip latency allows requests to settle before pending.size exceeds 128 on varying hardware.
Relocation commit:
Introduced in a628e57 and retained in 35f38e9.
