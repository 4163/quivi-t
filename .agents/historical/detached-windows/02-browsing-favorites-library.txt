Finding 02-01: Manhwa strip settle event omitted from workspace session event forwarding
Priority: P2
Confidence: Confirmed
Trigger and failure location:
- src/js/viewer/manhwaStrip.js:1858
- src/js/shared/workspaceSession.js:201-206
- src/js/shared/workspaceControls.js:9, 20-24, 69-70
- src/js/filepanel/filePanel.js:3077-3082

User interaction sequence:
1. User detaches the File List window (Windows > File List > Detached).
2. User opens a folder or archive in Manhwa mode (vertical continuous strip).
3. User scrolls through the strip in the main viewer window until scrolling decelerates and comes to rest (settles).
4. User observes the detached File List and Favorites panel.

Expected behavior:
When scrolling settles in the main viewer strip, the settled anchor item should be selected in the detached file list, and all visible images currently displayed in the strip should be marked with the in-view highlight (.in-view class) in the detached Favorites list.

Actual behavior:
The detached File List does not update its selection, and the detached Favorites list does not update its in-view highlights when strip scrolling settles. The highlights only update if the user performs an explicit navigation command (e.g., arrow keys) or another state snapshot is pushed over IPC.

Causal chain:
1. In src/js/viewer/manhwaStrip.js:1858, when the strip scroll comes to a complete rest, manhwaStrip dispatches the custom event quivit-manhwa-settle on the main window.
2. In src/js/filepanel/filePanel.js:3077-3082, the file panel attaches an event listener:
   window.addEventListener('quivit-manhwa-settle', () => {
     if (Core.getState().fileListVisible && _isManhwaActive()) {
       updateSelection(Core.getState().index);
       updateFavoritesSelection(Core.getState());
     }
   });
3. In attached mode, this listener executes locally on the main window and updates both the file list selection and the favorites in-view markers.
4. In detached mode, the file panel DOM runs inside the workspace-file-list replica window.
5. In src/js/shared/workspaceSession.js:201-206, the main window bridges custom events to peers:
   for (const name of ['quivit-favorites-changed', 'quivit-library-updated', 'quivit-download-complete',
     'quivit-download-status', 'quivit-refresh-start', 'quivit-refresh-end', 'quivit-workspace-import-activity', 'quivit-workspace-strip-info']) {
     window.addEventListener(name, event => {
       for (const label of peers.keys()) send(label, { kind: 'event', name, detail: event.detail }).catch(console.error);
     });
   }
   Notice quivit-manhwa-settle is omitted from this list.
6. In src/js/shared/workspaceControls.js:69-70, workspaceControls listens for quivit-manhwa-settle on main and calls publishStripInfo(), which dispatches quivit-workspace-strip-info with visible indices.
7. While quivit-workspace-strip-info is forwarded to the replica window, src/js/shared/workspaceControls.js:9 only records event.detail into a local variable (remoteVisibleIndices). It neither re-dispatches quivit-manhwa-settle nor notifies filePanel.js.
8. Because filePanel.js does not listen for quivit-workspace-strip-info and never receives quivit-manhwa-settle in the detached window, updateSelection and updateFavoritesSelection are never invoked upon scroll settle.

Commit attribution:
Introduced in commit a628e57 when workspace event forwarding was established, and unaddressed in commits 47b7043 and 35f38e9.


Finding 02-02: Library relocation listener early returns on replica windows, bypassing thumbnail cache invalidation
Priority: P3
Confidence: Conditional Risk
Trigger and failure location:
- src/js/main/main.js:341-346
- src/js/filepanel/filePanel.js:85-88

User interaction sequence:
1. User detaches the File List window (Windows > File List > Detached).
2. User browses image files and favorites in the detached File List, populating thumbnailCache and favoritesThumbnailCache in the detached window.
3. User opens Options (Windows > Options or 5) and relocates the Library folder to a new path on disk.
4. The backend completes relocation and emits the library-relocated Tauri IPC event to all open frontend windows.

Expected behavior:
Both windows receive the library-relocated event. The detached File List window (which actively renders and caches thumbnails) invokes clearLibraryPathCaches() to invalidate existing cached thumbnails associated with old library paths.

Actual behavior:
The listener in src/js/main/main.js:341-346 contains an explicit guard that aborts execution on any window where workspaceSurface is defined:
listen('library-relocated', (event) => {
  if (workspaceSurface) return;
  reloadConfigAndSyncLibrary(event.payload).catch(err => {
    console.error('[Main] Failed to activate relocated Library:', err);
  });
});
Because the detached File List window runs with workspaceSurface = 'fileList', it immediately returns without executing reloadConfigAndSyncLibrary. Consequently, clearLibraryPathCaches() is only called in the main window (where the file panel is hidden and thumbnail caches are unpopulated). The detached window retains stale thumbnail cache entries until natural LRU eviction occurs.

Causal chain:
1. When Library relocation occurs, src-tauri/src/commands/options.rs emits library-relocated to all windows.
2. In the main window, workspaceSurface is null. Main executes reloadConfigAndSyncLibrary, calls UrlLoader.handleLibraryRelocation, and runs clearLibraryPathCaches().
3. However, main is not hosting the file list DOM (hostsWorkspaceSurface('fileList', state) is false), so main's local thumbnailCache is empty.
4. In the detached window, workspaceSurface is 'fileList'. The guard if (workspaceSurface) return; causes the detached window to ignore the event completely.
5. In the detached window, clearLibraryPathCaches() is never called, leaving thumbnailCache and favoritesThumbnailCache containing stale path keys from the previous library location.

Commit attribution:
Introduced in commit a628e57 when replica window event guards were added in main.js, and preserved in commits 47b7043 and 35f38e9.


Intentional local and coordinated behaviors:

1. File list surface exclusivity and suppression of background rendering:

When triggered inside the detached window, the action executes locally in that window's context. 4. Detached window close intercept and session pair lifecycle:
In src-tauri/src/windows.rs and src/js/main/workspace.js, closing the detached File List window intercepts the native close event and emits workspace-close-requested. This triggers a coordinated teardown of the detached window while returning the workspace layout to the docked position on main, preventing orphan sessions or crashed IPC pipes.
