Relocation commit: a628e57 (Added window relocation and detach support)

Minimal user sequence:
1. Detach workspace panels into separate windows (Windows -> File List -> Detached).
2. Minimize the main window (viewer) to the Windows taskbar, leaving the File List window active on screen.
3. From the File List window, press shortcut '5' (or select Options from the menu), or click the Archive Info metadata badge button.

Expected behavior:
The Options or Metadata window opens centered on the active display monitor or over the active File List window where the user interacted.

Actual behavior:
The auxiliary window is created off-screen at coordinate (-32000, -32000) and becomes invisible and unreachable to user clicks.

Causal chain:
1. In single-window mode prior to commit a628e57, user interaction while main was minimized was impossible because only one window existed. Commit a628e57 introduced the detached File List window without updating auxiliary window positioning logic.

5. center_window_over_main invokes main.outer_position(). On Windows, when a window is minimized to the taskbar, Windows Win32 API returns minimized placeholder coordinates of (-32000, -32000).
6. center_window_over_main does not check main.is_minimized(), calculates x = -32000 + ... and y = -32000 + ..., and calls window.set_position(PhysicalPosition::new(x, y)).
7. The auxiliary window then executes window.show() and window.set_focus(), but is located off-screen at (-32000, -32000). The user sees no window appear.
