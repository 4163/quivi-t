# QuiviT architecture decoupling and performance roadmap

Continuation plan for refactoring, decoupling monolithic modules, resolving `validate-changes` violations, and optimizing hot paths across QuiviT. Designed so any cold agent on any harness can pick up from the current tree without handoff context.

## Locked rules and workflow

### 1. State markers
- `[ ]` **Pending:** Not yet started.
- `[~]` **In progress:** Active work in the working tree.
- `[-]` **Agent-verified and complete:** Verified directly by the agent via code inspection and automated checks (`node --check`, `npm run mocha`, `cargo check --tests`, `cargo test`, or `[Telemetry B]` parity). Examples include dead-code removal, visibility tightening, pure helper extraction, and self-explanatory logic changes fully proven by automated tests without needing human visual signoff. These are illustrative examples rather than a strict boundary; apply `[-]` to any other item whose correctness is completely verifiable by code inspection and automated tests.
- `[x]` **User-verified and complete:** Signed off by the user after manual runtime verification of UI, layout, interaction, or cross-window behavior.
- `[o]` **Deferred:** Deferred to a later slice item. Considered resolved in place once linked. Both the deferred item (`-> Slice X.Y #N`) and the destination item (`<- Slice A.B #M`) must link to each other.

### 2. Roadmap hygiene and anti-changelog rules
- **Present state only:** This file tracks current state and remaining work, never history. If a target path, line range, or design detail needs adjustment, edit the item in place. Never append *"Update:"*, *"Previously:"*, *"Changed from X to Y"*, timestamps, commit hashes, or session logs.
- **Marker-only completion:** Completing an item flips `[ ]` or `[~]` to `[-]` or `[x]`. Do not paste test outputs or telemetry summaries into this file.
- **Single-line checklist items:** Keep each checklist item to one concise line:
  `- [ ] **#ID Symbol or scope** (\`path:line\` -> \`target\`): Action and accept criteria. [Ref: audit-0X:L#]`
- **Hybrid audit references:** Execute directly from the checklist instruction. Open the referenced `.agents/major-refactor/audit-0X-*.md` line range only when you need the deeper root-cause trace or code snippet.

### 3. Per-slice telemetry and commit pipeline
For this refactoring branch, the `AGENTS.md` prohibition on creating or expanding test harnesses during implementation is lifted. Because structural splits break internal module hooks, every slice in Phases 1 through 6 must start with `#X.Y.0 [Telemetry A]` and end with `#X.Y.N [Telemetry B]`:
1. **Targeted telemetry generation:** Do not run full test suites during slice iteration. Target the test harness matching the layer being changed, and write a structured JSON artifact to `.agents/major-refactor/telemetry/slice-X.Y-{a,b}.json`:
   - **Frontend pure unit (`mocha/`):** `npx mocha <spec> --reporter json` (saved as UTF-8 without BOM).
   - **Backend Rust (`src-tauri/src/tests/`):** Targeted `cargo test <filter>` capturing execution JSON.
   - **Desktop E2E (`e2e/specs/`):** Targeted spec `npm run e2e -- --spec <spec>` saving test run telemetry.
   - **Replay Diagnostics (`e2e/replay-diagnostics/`):** `npm run diagnose -- <scenario>`, copying scenario report from `e2e/replay-diagnostics/reports/<scenario>-report.json`.
2. **`[Telemetry A]` baseline capture (`#X.Y.0`):** Expand test coverage against existing pre-refactor code and callers to cover all contracts touched by the slice. Run the targeted harness, save `.agents/major-refactor/telemetry/slice-X.Y-a.json`, and pause for commit. Strict gate: No subagent may touch production code or execute `#X.Y.1` onward until `#X.Y.0` is verified and committed.
3. **Slice implementation (`#X.Y.1` onward):** Execute production changes in order. Run static checks (`node --check`, `cargo check --tests`) and targeted tests during iteration.
4. **`[Telemetry B]` verification capture (`#X.Y.N`):** Update test imports for extracted modules, run the targeted harness to save `.agents/major-refactor/telemetry/slice-X.Y-b.json`, and verify 1:1 functional/UX parity against Telemetry A before committing.

### 4. Accepted `[Telemetry A]` to `[Telemetry B]` deviations
End-user functionality, visual output, keyboard/mouse UX, IPC command names, and `quivit://` URLs must match `[Telemetry A]`. Only deviations that represent intentional refactor, architectural, or performance wins are accepted. The items below are illustrative examples and are not exhaustive; any other measurable improvement or structural cleanup introduced by the refactor that preserves UX and functional parity should also be evaluated and accepted:
- **Lower notification and RPC counts:** Fewer `Core.onStateChange` calls per action (for example, `setManhwaMode` and `setSpreadMode` dropping from 2 notifications to 1) and fewer `workspaceSession` broadcasts (no per-frame `JSON.stringify(state.config)` serialization during pan/scroll).
- **Eliminated visual and layout anomalies:** Zero `blackout` frames during the 45ms bridge swap handoff, and zero `ty-teleport` jumps when neighbor dimension probes resolve in manhwa view.
- **Stable DOM node counts:** Constant DOM node counts across directory/archive changes, strip scrolling, and keybind edits due to node pool recycling in `#file-list`, `#favorites-list`, `#library-panel`, `.ico-size` cells, `.manhwa-volume` pills, and `.keybind-tags`.
- **Zero forced synchronous layouts and narrower style invalidation:** Eliminated mid-frame write-then-read `offsetWidth` and `getBoundingClientRect` flushes, and narrower style recalculation subtrees after replacing `body.foo *` rules and inline `style.*` writes with host/leaf classes and CSS custom properties.
- **Eliminated IPC chatter and lock stalls:** Zero 16ms `cursorPosition` IPC calls during keyboard pan, zero self-triggered `config-changed` reloads on save, shorter `RwLock<ArchiveCache>` hold times without 30-second write-lock blocks on header probes, and parallel thumbnail decoding without the global `DECODE_LOCK`.
- **Deterministic memory, blob, and VRAM bounds:** Single `URL.revokeObjectURL` calls on eviction, bounded `NATIVE_ICON_CACHE`, zero-copy `Arc<[u8]>` responses in `protocol.rs` and `image_pane.rs`, and expiring drop leases in `platform/drop.rs`.
- **Direct internal module imports in unit tests:** Unit tests in `mocha/` and `src-tauri/src/tests/` importing extracted pure domain modules directly while UI selectors and IPC contracts stay unchanged.

### 5. Architectural invariants
- **Single-owner split gate:** Never split a single DOM surface owner into sibling files that mutate the same DOM container. Extract pure math, state machines, parsers, and schedulers into `services/` or domain folders while keeping one UI writer per surface.
- **Surface-aligned CSS stylesheets:** Keep design tokens, resets, and shared primitives in `src/css/global.css`. Decompose `src/css/main.css` into `src/css/main/{workspace,menubar,file-panel,viewer,manhwa,statusbar,overlays}.css` and `src/css/options.css` into `src/css/options/{options,keybinds,associations,custom-css}.css` (one sheet per UI surface owner, linked directly via `<link rel="stylesheet">` in `<head>` before `<style id="custom-css"></style>` and `themePrePaint.js`, never via CSS `@import`). Keep `src/css/metadata.css` and `src-tauri/src/platform/previews/windows/preview_player.css` as single sheets.
- **Defer docs to Phase 7:** Do not edit `README.md` or `.agents/architecture-state.md` during Phases 0 through 6.
